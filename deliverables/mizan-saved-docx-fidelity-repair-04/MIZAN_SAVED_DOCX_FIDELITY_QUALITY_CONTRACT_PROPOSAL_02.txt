2. Rule R1 — objective identifier form and count

Existing rule. When is_rel32_compiler_first is true,
validate_saved_snapshot_original counts vision lines matching the
multiline expression ^\|\s*\d+\s*\|. A count below 8 appends
rel3_generation_contract_failed:objectives. Compiler-first is true when
document_type is strategy, flags contain rel3 and rel31, the normalized
domain is an authoritative domain, and the language prefix is ar.
Arabic DT strategy with those flags is in that set. When compiler-first
is false, the helper appends
saved_docx_fidelity_refused:objective_rule_unverified and does not apply
a second objective grammar. A missing domain returns
rel33_export_domain_missing:roadmap_quality before the objective count.
An exception in the compiler-first lookup appends
saved_docx_fidelity_refused:validator_exception:objectives.

Proposed rule. Retain that form, that count of 8, and those failure codes.
An accepted objective row, for this decision, is a vision line whose first
cell is one or more digits. OBJ-DT-01 is not an accepted form under this
counter. Each matching line increments the count, including a repeated
digit-led line. The helper has no separate duplicate-objective defect, no
malformed-token defect beyond failure to match the expression, no
registry-membership test, and no dangling-reference test. Those absences
are retained. Adding them would be a new policy, and no saved-fidelity
requirement read here defines them.

Scope. Original vision string on the saved preserve path, fresh and reused,
both handlers, for the route that entered rel3_export_authoritative.
Failure codes. The codes in the existing-rule paragraph.
Call sites. validate_saved_snapshot_original at proposed
rel31_authority.py 986-992. Fresh caller 1028-1031. Reused caller
1657-1660. Compiler-first predicate: rel32_compiler.py is_rel32_compiler_first
166-179, delegating to rel33_authority.py is_rel33_compiler_first 55-65.
The wrapper supplies flags at app.py 52226-52229.

3. Rule R2 — roadmap row minimum

Existing rule. check_roadmap_coverage sets
visible_row_count = max(unique parsed rows, number of required families
present). It appends roadmap_row_count:{visible_count} when that value is
below 10. The saved helper, if the visible count is below 10 and no
defect already starts with roadmap_row_count, also appends
roadmap_row_count_low. Any defect list is returned as
rel3_generation_contract_failed:roadmap_weak_output plus
saved_docx_original_roadmap_defect:{defect} for each defect.
There is no second numeric minimum that counts only physical table rows
apart from this visible_row_count rule.

Proposed rule. Retain visible_row_count of at least 10 as the only numeric
roadmap minimum on the pre-writer saved decision. Retain the formula
max(unique parsed rows, families present). Do not add a separate actual-row
minimum, and do not replace 10 with another number. An intentional absence
of a second actual-row minimum is this rule: completeness for the count is
the visible_row_count formula already computed by check_roadmap_coverage,
together with the family, duplicate, weak-output, and weak-owner defects
in R3, R4, and R5.

Scope. The joined original section strings on the saved preserve path,
fresh and reused. The domain argument is the normalized backend domain.
Failure codes. rel3_generation_contract_failed:roadmap_weak_output and
saved_docx_original_roadmap_defect:roadmap_row_count:{n} or
saved_docx_original_roadmap_defect:roadmap_row_count_low.
A validator exception appends
saved_docx_fidelity_refused:validator_exception:roadmap and returns before
the defect list.
Call sites. Helper 993-1010. Coverage function
rel27_export_checks.py check_roadmap_coverage 548-553.

4. Rule R3 — unique identifiers and duplicates

Existing rule. The coverage checker dedupes by the full row blob. A
repeated blob appends roadmap_duplicate_rows and is not counted again as
a unique row. There is no separate minimum number of distinct identifier
tokens such as RM-DT-nn.

Proposed rule. Retain the row-blob identity and the duplicate defect.
The explicit completeness criterion that replaces a separate unique-id
minimum is: one unique row is one distinct row blob; a repeated blob is
roadmap_duplicate_rows; the numeric gate remains R2. No minimum count of
distinct RM-DT identifiers is added.

Scope. Same joined original text and same domain as R2.
Failure code. saved_docx_original_roadmap_defect:roadmap_duplicate_rows,
under the collapsed rel3_generation_contract_failed:roadmap_weak_output.
Call site. rel27_export_checks.py 501-507 and 554-555, surfaced by the
helper at 1006-1009.

5. Rule R4 — required DT family set

Existing rule. For domain dt, resolve_roadmap_families returns the ten
DT_ROADMAP_FAMILIES names listed in section 1. A family absent after row
detection and token detection appends missing_family:{family}. Family
presence can raise visible_row_count. It does not erase a missing_family
defect, a duplicate, a weak output, or a weak owner.

Proposed rule. Retain that exact set of ten names as a requirement
separate from the row count. All ten are required for a coverage result
with no missing_family defect. Catalog tokens may mark a family present.
They do not replace the ten-name set and they do not lower R2.

Scope. Saved preserve path, explicit domain dt. Another domain keeps its
own family tuple. This proposal does not change other domains.
Failure code. saved_docx_original_roadmap_defect:missing_family:{family}.
Call sites. rel32_registries.py resolve_roadmap_families 491-498.
rel33_domain_substance.py DT_ROADMAP_FAMILIES 1226.
check_roadmap_coverage 537 and 556-557.

7. Rule R6 — pillar names

Existing rule. check_pillars_after_strategic_heading returns no defect
when neither الركائز الاستراتيجية nor الركائز is present. When either
heading marker is present, every domain catalog heading must appear.

Failure codes. The R1 and R2 codes. A blank domain at the authoritative

9. Rule R8 — what text may change before evidence

Existing rule, retained.
The pre-writer decision reads the original section strings joined by a
blank line. It does not normalize business text, does not repair Arabic
glue, and does not replace the snapshot. On refusal, those strings are
what the blockers describe, and the fresh preserve branch assigns those
same strings back.
The earlier equivalence check compares the canonical section_to_markdown
rendering with the snapshot signature under the saved-markdown grammar.
That comparison is the F003 source check. It is not the objective or
roadmap decision.
After a quality pass, the writer may draw the preserved source flow.
Returned-byte evidence then extracts visible text from the file bytes.
Extraction can break lines and tables. The extracted string, the
post-extraction hook string, the channel-local string, and the source
markdown remain different objects.
Equal returned-byte hashes show that the bytes given to the client match
the bytes given to evidence. They do not show that every later textual
decision used unmodified source markdown.
Business-text repair before this pre-writer decision stays excluded.
The repair helpers that delete duplicate roadmap rows or replace weak
output cells stay unwired on this path.

13. Fixture outcome under the specified rules

The unchanged fixture and EXPECTED stay unchanged. This section uses the
previously recorded fixture text: four vision rows whose first cells are
OBJ-DT-01, OBJ-DT-02, OBJ-DT-03, and OBJ-DT-04, and two roadmap data rows
RM-DT-01 and RM-DT-02. No new validator, parser, or numeric probe was run.

does not publish a new coverage defect list for the fixture. Refusal is

ever produced, the downstream pillar rule would require the four DT
catalog headings. Contract R does not require the fixture to pass, and
Repair 04 does not generate rows, rename OBJ-DT identifiers, or inject
catalog sentences to make it pass.

The declined fixture-sized alternative is stated completely so it is not
an unspecified option: minimum actual roadmap rows 2, minimum unique

accepted objective form OBJ-DT- followed by digits, objective count 4,
pillar catalog optional. That alternative is not recommended. No source
requirement read for this proposal treats two saved rows or four OBJ-DT
rows as completeness. It is not selected, and it is not implemented.
